# Coding Standards

- Match the repository's existing formatter, linter, naming, and file organization.
- Prefer explicit, readable code over clever code.
- Keep functions focused.
- Remove dead code introduced by the current change.
- Avoid hidden global state.
- Treat types and validation as contracts.
- Never swallow errors silently.
- Comments explain why, not obvious syntax.
- Do not introduce a dependency for functionality already available in the stack.
- Do not perform unrelated refactors while implementing a focused task.
