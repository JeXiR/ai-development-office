# Reference-Driven Development

Use when the user says:
- "look at this old project"
- "use this template"
- "check docs/references"
- "make it like this screenshot"
- "use this Figma design"

## Reference priority
1. explicit current task requirements
2. current project architecture/docs
3. current project design system
4. referenced source
5. general best practices

A reference must never silently override current business/security constraints.

## Process
1. identify reference type
2. read its registration doc if present
3. inspect only relevant source areas
4. extract patterns/behavior
5. list conflicts with current project
6. adapt
7. QA
