# Project Discovery & Roadmap Workflow

## Phase 1 — Discover
1. Inspect docs directory recursively.
2. Inspect repository structure.
3. Identify roadmap/product/specification documents semantically.
4. Classify documents.
5. Determine whether enough project intent exists.

## Phase 2A — Existing roadmap/docs
6. Read primary roadmap/product/architecture sources.
7. Detect duplicates, stale files, contradictions and placeholders.
8. Normalize docs safely.
9. Establish canonical roadmap.
10. Verify roadmap items against repository evidence where practical.
11. Build/reconstruct PROGRESS.md and PROJECT_STATE.md.
12. Set current-task.json.

## Phase 2B — No useful roadmap/docs
6. Ask only: "What do you want to build?"
7. From the answer create:
   - product vision
   - requirements
   - roadmap
   - architecture baseline
   - feature docs
   - decision queue
   - operations baseline
8. Then generate PROGRESS.md and PROJECT_STATE.md.

## Phase 3 — Continue
13. `status` reports derived project state.
14. `review project` performs deep implementation audit.
15. Verified audit findings feed back into roadmap/progress.
