# Project Workbench

AI Development Office v0.7 treats project work as evidence-backed work items, not only findings.

## Sources

- PROGRESS.md Todo
- PROGRESS.md Next Actions
- docs/ROADMAP.md checkboxes
- docs/testing/TEST_GAPS.md
- docs/testing/TENANT_ISOLATION.md
- security findings
- generated frontend coverage audit

## Work lifecycle

todo -> queued -> working -> done

Alternative states:

deferred
blocked

## Rule

A historical TODO document is input, not truth.
Work item completion should only become durable when repository/test/build/project-state evidence supports it.
